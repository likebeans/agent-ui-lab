# W3：A2UI 兼容、校验与编辑冲突

打开 [A2UI 兼容与编辑冲突实验](#labs/a2ui-compatibility)，观察同一份表单遇到能力限制、无效输入和远端更新时的行为。实验使用 A2UI 0.9.1 教学子集与原有六种组件；业务修订号、校验规则和冲突选择属于应用层约定。

## 先看清三层数据

| 数据      | 放在哪里                                       | 用来做什么                                                     |
| --------- | ---------------------------------------------- | -------------------------------------------------------------- |
| A2UI 消息 | 响应 `snapshot.messages`                       | 创建 Surface、写入模型、声明组件；不添加业务版本字段           |
| 应用快照  | `documentId`、`revision`、`surfaceId`、`rules` | 标识同一份服务端文档，检查版本与动态字段规则                   |
| 用户草稿  | 浏览器 `DraftState`                            | 保存原始基线、当前输入与待解决冲突；尚未提交不代表服务端已更新 |

检查器会分别记录完整应用响应与原始 A2UI 消息。展开“查看证据与应用边界”可观察字段规则与保存的动作，也可定位组件声明。

## 实验一：能力检查与文字降级

1. 保持“标准旅行表单”，点击“创建表单”。Renderer 使用本地注册的 basic catalog 和六种组件。
2. 勾选“模拟不支持 ChoicePicker 的客户端”。表单会切换为可读文字，解释无法渲染的组件。
3. 取消勾选，原草稿仍保留。
4. 点击“重置并使用新 ID”，选择“未知 catalog”或“未知组件类型”，再创建表单。
5. 检查降级理由与文字结果，观察网络请求：catalog URI 不会被下载或执行。

能力检查在严格解析与渲染之前执行；拒绝不支持的声明，不把未知内容交给任意 HTML 或 JavaScript 渲染器。当前仍只支持项目自己的教学 catalog 子集，不代表完整 A2UI 兼容实现。

## 实验二：客户端字段与服务端业务校验

1. 创建标准表单，保留空姓名，点击“生成计划”。客户端显示字段错误，没有发送动作。
2. 用键盘进入错误摘要，激活错误链接，焦点会回到对应输入。错误下方显示组件 ID、绑定路径和动作名。
3. 填写姓名，将天数填成 `8`，观察范围错误；恢复为 `2`。
4. 点击“远端增加预算字段”。新的 `TextField`、模型值、按钮 context 和应用字段规则一起出现，仍使用同一个 Renderer。
5. 将预算填成 `100` 后提交：它符合整数格式，但服务端业务规则要求预算至少为“天数 × 500 元”，因此拒绝。
6. 将预算改为 `2000` 后提交，观察“成功动作”计数与服务端回复。

客户端校验方便用户修正，服务端会重新校验。服务端不能相信客户端曾运行过规则。字段错误和业务错误均关联到具体组件与绑定；规则通过应用快照传递，没有冒充 A2UI 0.9.1 新字段。

## 实验三：远端更新遇到未提交输入

1. 创建标准表单，天数初值为 `2`。改为 `5`，先不提交。
2. 点击“远端延长一天”，服务端值变成 `3`。页面读取新快照后保留 `5`，显示原值、草稿和远端值。
3. 点击“保留我的行程天数”，草稿保留 `5`，下一次提交以最新业务版本为前提。
4. 再修改字段并触发远端更新，选择“采用远端行程天数”，确认输入使用远端值。
5. 尝试在冲突未解决时重复读取：未解决的冲突不会自行消失，也不会静默覆盖草稿。

未修改字段可以接受远端更新。双方修改同一字段时必须明确选择；同值更新不需要制造冲突。草稿基线、组件绑定变化和待解决选择由共用 `draft.ts` 处理。

## 本地两个页面验证

本地模式运行 `npm run dev` 后：

1. 页面 A 创建表单，复制“文档 ID”。
2. 页面 B 打开同一实验，粘贴 ID，点击“读取远端”。两页显示相同文档与业务版本。
3. A 修改天数为 `5`，B 点击“远端延长一天”。
4. A 点击“读取远端”，确认草稿仍为 `5`，冲突中远端值为 `3`。
5. A 填写有效姓名，保存当前动作；B 再更新业务版本。
6. A 发送已保存动作。服务端返回版本冲突，不执行动作，成功计数不增加。

本地文档保存在当前服务端进程内存，重启后清空。Pages 使用同一业务逻辑的页面内存实例，不同浏览器页面不共享状态；在同一页面使用“远端”按钮验证合并算法，不能把它当成跨页面后端并发。

## 实验四：过期 action 与 Surface

1. 填写有效输入，点击“保存当前动作”。这只保存带 `expectedRevision` 的应用 envelope，没有发送。
2. 点击“远端延长一天”，再“发送已保存动作”，观察版本拒绝与计数不变。
3. 重新保存有效动作，点击“远端重建 Surface”，再发送旧动作。
4. 确认服务端拒绝旧 Surface，并返回最新快照。输入可按冲突规则合并，旧动作不会被自动重发。
5. 检查最新值后，通过当前表单按钮重新生成新动作并提交。

也可在保存动作后继续修改输入，再发送这份仍有效的已保存动作：服务端执行的是保存时的值，界面以这份已提交输入为比较基线，继续保留后来的草稿，即使你把字段改回创建时的初值。若已保存动作的旧值校验失败，错误不会标到已改变的当前输入上；可通过表单按钮重新提交当前值。

保存动作同时绑定当前文档 ID。修改输入框里的 ID 尚未切换当前文档，读取不存在的文档也不会清除原动作；成功读取另一份文档后，原保存动作会清除，必须在新文档重新保存。同一文档的版本更新或 Surface 重建仍保留旧动作，供上面的过期动作实验使用。

`expectedRevision` 位于 action 外层，Surface ID 仍是 A2UI action 原生身份。服务端检查动作类型、来源组件、参数结构、当前 Surface 与业务版本。界面合并成功不等于业务动作已经执行。

请求超过 8 秒会恢复操作按钮，但超时不代表服务端没有执行。先“读取远端”核对业务修订和成功动作计数，再决定是否重新提交。保存动作后继续编辑的字段仍会保留，即使改回创建时的初值；未知结果下与远端不同的后续编辑需要明确选择。版本或计数增加本身不能证明是哪一个客户端的动作成功，因此不会把远端更新自动归因给这次请求。实验不会自动重发动作。

通用 HTTP 错误、非 JSON 或未知响应结构会显示错误并保留草稿；有效的业务校验与版本冲突仍分别处理。可先修复服务连接，再读取远端核对事实。

## 源码与接入

- `shared/labs/a2ui-compatibility/contract.ts`：应用快照、能力、字段规则和动作 envelope。
- `shared/labs/a2ui-compatibility/engine.ts`：权威内存状态、输入校验、业务校验、并发版本拒绝。
- `shared/labs/a2ui-compatibility/draft.ts`：能力检查、受控草稿与三方比较。
- `src/components/A2uiSurfaceRenderer.tsx`：抽取后的受控 Renderer，原有聊天与独立实验继续复用。
- `server/labs/a2ui-compatibility/index.ts` 与 `shared/labs/a2ui-compatibility/static.ts`：HTTP / Pages 同一输入输出适配。
- `src/labs/a2ui-compatibility/Lab.tsx`：交互与证据入口。

W3 已在 `server/labs/index.ts` 与 `shared/labs/static-handlers.ts` 登记，与 W1/W2 同时可用。它保留独立内存引擎，不依赖任务数据库，没有新增依赖或引入新协议版本。
