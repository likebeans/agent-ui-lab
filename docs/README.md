# Agent UI 学习地图

这个项目的目标是让你从可操作的界面出发，追到协议消息、数据模型和服务端实现，最后能独立开发一个智能交互功能。

## 先分清四个角色

- **模型 / Agent**：决定下一步要说什么、调用什么工具、提出什么界面。这个项目先用确定性代码代替决策，避免模型不确定性干扰协议学习。
- **协议**：约定双方交换的消息形状、时序和能力。
- **业务服务**：验证输入、查询数据、执行动作。协议不能替代业务鉴权和数据一致性。
- **前端 / Host**：消费事件、渲染组件、提供用户交互、执行宿主策略。

## 三个协议解决的问题

| 协议     | 核心问题                           | 传输的主要内容                         | 独立实验入口 |
| -------- | ---------------------------------- | -------------------------------------- | ------------ |
| AG-UI    | Agent 在执行过程中发生了什么？     | 生命周期、文本增量、工具调用、共享状态 | `/#agui`     |
| A2UI     | 该出现哪些组件，组件绑定什么数据？ | 声明式组件、数据模型、用户动作         | `/#a2ui`     |
| MCP Apps | 工具如何提供一个可交互的应用？     | 工具元数据、UI 资源、App / Host 消息   | `/#mcp`      |

它们处理不同层的问题。AG-UI 处理 Agent 与界面的事件交互；A2UI 描述界面；MCP Apps 让 MCP 工具附带应用。首页 `/#chat` 将三种能力放进同一段连续对话：规划行程 → 生成需求表单 → 打开城市活动应用。城市和天数会沿对话传递，生成的表单与应用保留在各自的消息中；表格中的独立实验入口用于进一步拆解。

当前的 `/api/chat` 是本项目自定义的规则路由，根据关键词或手动选择决定本轮展示方式。它不是三个协议的一部分，也没有使用 LLM。示例没有把 A2UI 或 MCP Apps 消息封装进 AG-UI；它演示的是同一个聊天宿主如何消费不同协议。

A2UI 也不是 **A2A**：A2A 面向 Agent 间通信；A2UI 面向 Agent 输出的界面描述。

第一次打开项目，可以先按 [30 分钟对话](./00-first-session.md) 走完一遍，再用 [从观察到独立开发](./07-learning-method.md) 做修改和预测实验。熟悉基础表单后，可进入 [W3：A2UI 兼容、校验与编辑冲突](./labs/a2ui-compatibility.md)，学习能力降级、动态字段规则、草稿合并与过期动作拒绝。

## 在前端阅读完整教程

聊天顶部的书本图标、侧栏“学习文档”和回复底部的协议教程链接，都可以进入阅读器。独立实验也提供同样的入口。阅读器直接加载本目录的 Markdown 与项目 README；全文搜索、全部章节、本章目录和上一章／下一章都可在前端使用。点击标题旁的 `#` 可获得含章节位置的链接，浏览器前进／后退也能切换阅读位置。

用阅读页顶部的“返回 Agent 对话”或“返回独立实验”，可继续当前表单、App 和学习实验。打开文档会暂停 AG-UI 自动回放，真实请求仍会继续；返回后可手动继续回放。聊天和基础实验的界面状态仅存在内存中，刷新或新建对话会重置。本地 W1/W2 的任务与业务事实保存在 SQLite，可通过任务身份或查询恢复；Pages 的业务事实仍在当前页面内存中，刷新后清空。

## 在聊天里找到学习功能

| 目标               | 回复中的入口                                       | 应拿到的证据                                             |
| ------------------ | -------------------------------------------------- | -------------------------------------------------------- |
| 解释一次 UI 更新   | AG-UI：“追溯文字更新”或“事件如何变成这条回复”      | 同一条事件、更新前后状态、变化字段和源函数               |
| 理解组件如何生成   | A2UI：“声明如何变成 React 组件”                    | 组件 ID、绑定路径、React 控件与当前声明快照              |
| 修改声明并完成提交 | A2UI：“A2UI Workshop：改声明，观察同一个 renderer” | 有效草稿改变真实表单，预算进入 action 并被服务端回显     |
| 区分数据与资源     | MCP Apps：“动手验证 MCP Apps 因果链”               | 工具更新与布局切换触发不同的调用、资源读取和 iframe 挂载 |

三个面板都有“先预测，再验证”。先选答案再运行，最后读实际结果与证据；执行失败时本次不判分。学习进度与结果只保留在当前页面内存中。

## 建议的学习顺序

1. [AG-UI：从事件到 UI](./01-ag-ui.md)：运行一次，取消一次，再触发一次错误。
2. [A2UI：从声明到组件](./02-a2ui.md)：生成界面，改字段，提交动作，检查服务端更新。
3. [MCP Apps：从工具到应用](./03-mcp-apps.md)：发现工具，读取 UI 资源，完成握手，通过宿主调用工具。
4. [A2UI 兼容与编辑冲突](./labs/a2ui-compatibility.md)：验证能力降级、字段校验，保留草稿并拒绝过期动作。
5. [任务恢复与事件重放](./labs/task-recovery.md)：断开接流后恢复同一 run，对照 checkpoint、游标与工具计数。
6. [人工确认与业务事实](./labs/human-approval.md)：审阅提议，确认或拒绝，丢失响应后查询事实并重试原命令。
7. [真实开发路径](./04-real-development.md)：迁移到真实 Agent、业务 API、会话与部署。
8. [练习清单](./05-exercises.md)：尝试修改协议消息和组件目录，并验证结果。
9. [消息对照速查](./06-protocol-reference.md)：在三个实验的检查器旁边对照阅读。
10. [从观察到独立开发](./07-learning-method.md)：事件追溯、声明编辑、资源对比与“先预测，再验证”的实际操作。

## 三遍读法

**第一遍只操作。** 先在聊天中完成规划、表单和应用操作，观察实际行为。回复底部可选中该轮协议消息，右侧检查器保留该轮最近 300 条消息；可以筛选事件名，查看 JSON，导出一份 trace。

**第二遍看边界。** 为每条消息标注发送方和接收方。注意哪些消息跨 HTTP，哪些跨 iframe，哪些只是客户端模型更新。

**第三遍做修改。** 先在聊天面板改一条事件、一份声明或一个工具输入，写下预测，再对照执行结果。随后从练习清单选一个源码改动，把同样的方法迁移到代码里。

## 先认识实验的范围

- 数据为教学样本。本地模式实际运行 HTTP / SSE、MCP Streamable HTTP 与 App 桥接；Pages 静态学习版在浏览器内运行事件、动作与 MCP 工具，App / Host 仍通过真实 `postMessage` 通信。界面与 trace 明确标记模式，见 [运行与部署模式](04-real-development.md#5-准备部署)。
- 没有调用 LLM，也没有访问真实预订、支付或天气服务。
- 本地 W1/W2 已有 SQLite 任务与报名事实，但尚无持久聊天会话或生产多租户鉴权。W3 本地文档属于服务进程内存；Pages 的三个进阶实验都使用页面内存模拟。
- A2UI 渲染器只实现文档列出的组件子集；支持版本以对应章节为准。
- MCP App 只加载本项目自行生成的资源；不要将这个最小 Host 当作任意第三方应用的托管环境。
