# A2UI：从声明到组件

本章对应 `/#a2ui`。实验实现的是 A2UI **v0.9.1** 的严格教学子集：服务端用确定性代码生成协议消息，浏览器根据白名单组件目录渲染原生 React 控件，再把结构化动作送回服务端。没有 LLM，也不会调用真实预订服务。

GitHub Pages 静态学习版在浏览器内调用 `shared/a2ui-agent.ts` 的同一 builder 和动作校验器，没有业务 HTTP 请求。组件渲染、绑定、动作和更新消息保持一致，检查器标记 `browser-memory`。本章请求与服务端描述对应本地模式；浏览器内校验只用于教学，见 [运行与部署](04-real-development.md#5-准备部署)。

基线源码：<https://github.com/a2ui-project/a2ui/tree/3eb145de4fca475c0d2ada076fd91bb22b0d98ec/specification/v0_9_1>

聊天入口复用同一个 Renderer，并增加按需求选择预算、同行人数字段，以及声明编辑、绑定预测和预算提交练习；操作步骤见 [从观察到独立开发](07-learning-method.md)。本章按钮和生命周期说明对应独立实验。

## 先看完整往返

1. 点击“生成 A2UI 界面”。浏览器请求 `POST /api/a2ui/surface`。
2. 服务端依次返回 `createSurface`、`updateDataModel`、`updateComponents`。
3. Renderer 从固定的 `root` 组件出发，按 ID 解引用扁平组件集合。
4. 修改目的地、姓名或天数。React 控件通过 JSON Pointer 写回本地数据模型。
5. 点击按钮。客户端从按钮声明中的路径解析 `destination`、`traveler` 和 `days`，构造 `action` 并请求 `POST /api/a2ui/action`。
6. 服务端验证动作，返回一条数据更新和一条组件更新。状态文字变化，按钮标签被完整替换。
7. 点击“删除 Surface 并重置”。客户端真实请求 DELETE 接口，收到 `deleteSurface` 后才清空界面。

右侧检查器会同时显示跨 HTTP 的消息与本地绑定写入。先按方向区分它们：本地编辑不是服务端协议消息。

## 四种消息

每条消息都使用同一个版本字段：

```json
{
  "version": "v0.9.1",
  "createSurface": {
    "surfaceId": "trip-planner",
    "catalogId": "https://a2ui.org/specification/v0_9/catalogs/basic/catalog.json"
  }
}
```

注意：协议版本是 `v0.9.1`，而 v0.9.1 Basic Catalog 的自标识仍包含 `v0_9`。不要自行把 URL 改成 `v0_9_1`。

实验支持四种顶层消息：

- `createSurface { surfaceId, catalogId }`：建立单个 Surface；已有活动 Surface 时重复创建会报错，不会静默重置。
- `updateDataModel { surfaceId, path, value }`：更新整棵或局部数据模型。
- `updateComponents { surfaceId, components }`：按组件 ID 更新声明。
- `deleteSurface { surfaceId }`：删除 Surface。

初始化顺序有意义：先创建，再写数据，最后提交依赖这些数据的组件。实验将 A2UI 根路径 `/` 归一化为 JSON Pointer helper 使用的空路径 `''`；其他路径必须保持绝对路径，例如 `/form/days`。这个严格教学子集要求 `updateDataModel` 总是携带 `value`，根值必须是对象，并且不实现“省略 value 即删除路径”的可选语义。

## 扁平组件，而不是嵌套 JSX

组件消息中的对象是扁平列表。父组件只保存子组件 ID：

```json
[
  { "id": "root", "component": "Card", "child": "form" },
  { "id": "form", "component": "Column", "children": ["title", "destination", "days", "submit"] },
  { "id": "title", "component": "Text", "text": "生成一份周末行程计划", "variant": "h1" }
]
```

根组件 ID 必须恰好是 `root`。`updateComponents` 是按 ID 的**完整对象替换**，不是浅合并。服务端若只想把按钮文字从“生成计划”变成“重新生成计划”，就发送完整的新 `Text` 对象。每条组件更新应用后，合并后的引用图必须立即完整；本实验不缓存跨消息的前向引用。

本实验的目录只允许六种类型：

| 类型           | 允许的结构                                               |
| -------------- | -------------------------------------------------------- |
| `Card`         | 一个 `child`                                             |
| `Column`       | `children` ID 数组                                       |
| `Text`         | 固定字符串或 `{ path }` 绑定；可选 `h1`、`h2`、`caption` |
| `TextField`    | `label` 与字符串绑定                                     |
| `ChoicePicker` | `mutuallyExclusive`、选项和绑定                          |
| `Button`       | Text 子组件和 event action                               |

`ChoicePicker` 即使是单选，绑定值仍是**字符串数组**，例如 `['hangzhou']`。Renderer 不接受 HTML，不执行 `eval`，也不会把协议内容当 JSX。Zod 在运行时拒绝未知组件、额外字段、错误类型、重复创建和未知 Surface；数据层拒绝缺少 `value` 与非对象根模型；图遍历还会拒绝缺失引用、循环与超过 64 层的结构。

## 数据绑定为什么能双向工作

字段只知道一个数据路径：

```json
{
  "id": "destination",
  "component": "ChoicePicker",
  "label": "目的地",
  "variant": "mutuallyExclusive",
  "options": [
    { "label": "杭州", "value": "hangzhou" },
    { "label": "成都", "value": "chengdu" }
  ],
  "value": { "path": "/form/destination" }
}
```

渲染时用 `readPointer` 读取当前值；用户编辑时用 `writePointer` 产生一份新的模型。组件声明没有变化，因此结构与数据可以独立更新。这个本地写入会进入 trace，但方向是 `local`。

为了避免原型污染，JSON Pointer helper 拒绝 `__proto__`、`constructor` 与 `prototype` 路径，也拒绝非法转义。生产 Renderer 还应根据业务限制字段长度、输入类型和数据规模。

## 动作不是 `userAction`

v0.9.1 客户端动作的字段名是 `action`：

```json
{
  "version": "v0.9.1",
  "action": {
    "name": "save_trip",
    "surfaceId": "trip-planner",
    "sourceComponentId": "submit",
    "timestamp": "2026-10-22T03:00:00.000Z",
    "context": {
      "destination": ["chengdu"],
      "traveler": "学习者",
      "days": "3"
    }
  }
}
```

按钮声明只保存上下文路径。点击时，客户端读取当下模型并发送**已解析的值**。服务端不能信任客户端：它再次校验版本、Surface、来源组件、动作名、姓名长度、目的地白名单与 1–7 天范围。旧式 `userAction` 或多余字段会得到 HTTP 400。

这里的动作只生成 fixture 文案，不产生预订、支付或持久化副作用。接入真实业务时，服务端还要补鉴权、授权、幂等键、审计和事务边界。

## 错误、重试与生命周期

实验不会挂载即请求，必须由用户主动创建 Surface。每个请求有 8 秒超时并显示恢复路径：加载、动作或删除失败后，可以重试原操作。组件卸载时会中止所有进行中的 fetch，并在响应后检查挂载状态，避免卸载后的状态更新。

客户端只在成功解析整个响应后提交 React 状态。协议校验失败、组件图失败或绑定类型失败都保留原 Surface，并显示错误。这比“尽量渲染”更适合学习安全边界。

## 沿源码阅读

按下面顺序阅读最容易建立闭环：

1. `shared/a2ui.ts`：版本常量、Zod schema、消息 reducer、组件图验证、绑定与动作解析。
2. `shared/a2ui-agent.ts`：fixture Surface、动作验证与增量更新；`server/a2ui.ts` 负责 Express 路由。
3. `src/components/A2uiSurfaceRenderer.tsx`：共用六组件受控 Renderer、字段标签与错误关联。
4. `src/labs/A2uiLab.tsx`：请求生命周期、trace 与本地双向绑定。
5. `tests/a2ui.test.ts`：初始化、绑定、动作、完整替换、删除、循环与 HTTP 非法动作。

完成基础实验后，继续 [W3：A2UI 兼容、校验与编辑冲突](labs/a2ui-compatibility.md)，观察能力限制、动态字段规则、未提交草稿和过期动作。版本号与冲突策略保存在应用层，不加入原始协议消息。

## 动手练习

1. 修改某个 `Text` 的固定文案，预测只会影响哪个组件对象。
2. 给 `Column.children` 引用一个不存在的 ID，运行测试观察错误。
3. 把 `root` 改成引用自身，验证循环检测。
4. 增加一个受支持的 `TextField` 与数据路径；不要先扩组件目录。
5. 再设计第七种白名单组件：先写 schema 和失败测试，再实现 Renderer 分支。

完成后，你应该能解释：为什么服务端不需要发送 HTML、为什么数据模型能独立于组件树更新、为什么 action context 要在点击时解析，以及为什么声明式协议仍然需要严格的宿主安全策略。
