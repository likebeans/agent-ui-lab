# 从观察到独立开发

聊天中的每个学习面板都围绕三个动作：找到原因、改变一个输入、用实验验证预测。目标是能解释和修改一次真实交互，而不只是认识协议名字。

## 先分清不同层

AG-UI 的事件回答“执行过程中发生了什么”，A2UI 的声明回答“宿主应该渲染哪些组件”，MCP Apps 约定“工具如何提供可运行的应用”。它们可以在一个产品中组合。输入框的“按需求选择示例”只是本地教学路由，不代表真实产品必须在三者之间三选一。

本项目仍没有连接 LLM。规则、声明、业务样本可预测；本地模式实际执行 HTTP、SSE、MCP 和 iframe 桥接。Pages 静态版在浏览器内生成事件、处理动作并运行 MCP 工具，iframe 桥接仍真实执行。以下“请求服务端”在静态版中对应浏览器内处理器，检查器会明确标记 `browser-memory`，详见 [运行与部署模式](04-real-development.md#5-准备部署)。明确区分本地实验记录与跨边界消息，是学习的一部分。

## 先知道每种操作会改哪里

| 操作                        | 影响范围                                       | 是否重新请求服务端                   |
| --------------------------- | ---------------------------------------------- | ------------------------------------ |
| AG-UI 暂停、单步或自动回放  | 本轮展示状态；真实事件流继续接收               | 否                                   |
| AG-UI 编辑事件并试运行      | 独立实验预览；原回复与后续上下文不变           | 否                                   |
| A2UI 应用草稿、运行绑定实验 | 本轮真实表单和内存模型                         | 否；点击表单按钮提交时才请求动作接口 |
| MCP 实验 A                  | 现有 App 收到新工具结果；聊天共享城市不变      | 是，调用工具                         |
| MCP 实验 B                  | 读取另一份 UI 资源并重建 App，复用最后工具结果 | 是，读取资源并重新进行 App 握手      |

A2UI 和 MCP 的“修改并观察”会影响上方可操作界面。A2UI 可重置到本轮初始声明；MCP 可重新打开应用，恢复本轮请求的初始城市与默认布局。通过“学习文档”阅读教程，或进入“独立实验与源码导读”，再返回 Agent 对话，会保留当前消息、表单、App、学习结果与检查器选择。聊天中已发起的请求继续接收；隐藏聊天会暂停自动回放，返回后可手动继续。刷新或新建对话会清空当前聊天与 trace。聊天和上次独立实验可以往返；切换不同独立实验仍会重新建立该实验界面。

## AG-UI：把一条回复拆成可重放的因果链

发送“帮我规划杭州三日游”。在消息里点击“暂停展示并观察”。暂停只冻结渲染状态，网络继续接收事件；运行状态显示真实服务端进度。回到实时可立即看到最新状态。

展开“事件如何变成这条回复”，使用上一步、下一步、从头回放和事件选择器。比较同一事件前后的状态，并看上方文字、工具卡片或任务区域的高亮。点击界面的“追溯”入口可以反向找到关联事件，再定位到右侧检查器的原始记录。

先预测：对已有文字追加一条 `TEXT_MESSAGE_CONTENT`，会覆盖还是追加？选择后执行“用本轮事件验证”。证据来自把实际记录的事件应用到实际记录的旧状态；结果不是根据你点了哪个选项生成的。

在事件选择器中先选一条 `TEXT_MESSAGE_CONTENT`，再展开“改一条事件，试运行 reducer”，修改 `delta` 并点击“验证并试运行事件”。这会以记录的旧状态为起点运行相同 reducer，下面显示实验结果。修改 `messageId` 为不存在的值，观察校验失败并保留上次有效预览。点击“恢复原事件”可以继续比较。真实对话和后续上下文不会被实验覆盖。

完成标准：能解释 `TOOL_CALL_END` 为什么不等于 `TOOL_CALL_RESULT`，能指出 `STATE_SNAPSHOT` 与 `STATE_DELTA` 的更新范围，并能根据一条事件预测具体的 UI 变化。

源码：`src/components/AguiLearningPanel.tsx`、`shared/agui-learning.ts`、`shared/agui.ts`。

## A2UI：把结构、绑定和动作拆开

先生成一个普通需求表单，再请求“生成带预算和同行人数的出行表单”，比较收到的组件树，而不只比较默认字段值。规则 builder 会根据这些要求选择额外字段；这演示结构生成的边界，并非模型自由编写代码。

展开“声明如何变成 React 组件”，选择一个声明，沿组件类型、绑定路径、模型值、React 元素追到实际控件。“在检查器中查看当前组件声明”会记录 renderer 当前使用的本地快照，包含已经应用的修改。

展开“A2UI Workshop：改声明，观察同一个 renderer”，一次只改一件事：布局中的一个子组件引用、一个绑定路径，或一个带绑定的预算字段。预设只填写 JSON 草稿，需要点击“验证并应用到真实界面”才会改变表单。

编辑器只接受 `{ components, model }`。点击“验证并应用到真实界面”会先校验 schema、组件引用图和绑定，再一次性应用到同一个 Renderer。合法结构会改变实际表单；非法路径、未知组件或循环引用会被拒绝，保留草稿与最后一次有效界面。

可以按顺序试三个预设：

1. **“布局引用移除（保留定义）”**：应用后姓名控件消失，但 `traveler` 组件定义仍在。解释“存在定义”和“从 root 可达”为什么不同。
2. **“错误绑定路径（应拒绝）”**：应用后应报告 `/form/notARealField` 不存在，上方表单保持有效状态。
3. **“预算字段 + action.context”**：应用后出现预算输入框；检查组件、模型、布局引用与提交上下文四处如何对应。

预设都从本轮最初收到的 Surface 生成，不是在现有草稿上叠加。点击“重置为初始声明与模型”会恢复初始表单，并清除该 Workshop 的实验反馈。

先预测：只改变一个 TextField 的绑定值，组件声明是否也会变化？执行“运行本地绑定实验”，观察模型前后的值与 `componentsUnchanged`。这一步没有发起业务 HTTP 请求；提交表单时才发送真实 `action.context` 并接收服务端返回。

动手任务：在普通表单里手动增加预算字段、模型值、布局引用和按钮动作里的预算绑定，也可先用预算预设观察完整结构。应用后填写姓名，把预算改为 `4200`，点击表单中的“生成计划”。检查请求的 `action.context.budget` 和服务端返回的“预算 4200 元”，再看“预算字段练习验证”是否全部完成。

声明通过校验只说明界面能被本地 Renderer 使用；动作仍受服务端支持范围限制。例如把按钮 ID 改成其他值，即使组件图合法，动作接口仍会拒绝不支持的来源组件。

源码：`shared/a2ui-agent.ts`、`shared/a2ui.ts`、`src/labs/A2uiLab.tsx`、`src/components/A2uiWorkshop.tsx`。

## MCP Apps：分别改变数据和界面资源

打开城市活动应用，展开“动手验证 MCP Apps 因果链”。沿工具定义的资源关联、实际 `resources/read` 响应、App 握手、工具结果看每个边界；每条记录可展开数据并定位协议检查器。宿主负责发现资源、隔离承载和代理；资源内部的 App 负责渲染活动。

先预测：只更换工具结果，必须重新读取 HTML 资源吗？在“实验 A 的工具输入城市”中选另一个城市，选择预测后调用工具。观察 App 的活动变化，以及资源读取、iframe 挂载和工具调用的前后计数。这些计数记录 Host 发起的操作；握手记录另行确认 App 是否就绪。实验只改变本轮 App，聊天的共享城市仍由 App 内的城市按钮更新。

再在“实验 B 的 UI 布局资源”中选择另一份资源并点击“读取所选资源并重载 App”。此时宿主实际读取另一个注册资源，重新创建 iframe 并握手，然后发送上一份真实工具结果。同一城市数据会以卡片或列表布局展示。这是教学 Host 的显式选择，工具元数据仍指向默认的 `ui://intelligent-ui/trip-picker`；列表资源为 `ui://intelligent-ui/trip-picker-list`。

单独执行每个实验时，应得到下面的增量；可以同时对照面板计数、协议检查器与上方 App 的活动内容：

| 操作                               | 新增 `resources/read` | 新增 iframe 挂载 | 新增 `tools/call` |
| ---------------------------------- | --------------------- | ---------------- | ----------------- |
| 实验 A：选择不同城市，更新工具结果 | 0                     | 0                | 1                 |
| 实验 B：选择另一份布局资源         | 1                     | 1                | 0                 |

若工具调用失败，预测题会显示“本次不判分”，原有数据保持可用；修复后可重试。资源读取记录中的 HTML 只显示文档标记、根节点与长度，完整 HTML 仍实际加载到 iframe。

完成标准：能解释“改变工具数据”和“改变 UI 资源”为什么会经过不同路径，能区分 MCP 初始化与 App UI 握手，并能指出界面代码在哪个运行环境执行。

源码：`shared/mcp-server.ts`、`src/labs/McpLab.tsx`、`src/mcp-app.ts`。

## 离开示例，检验能否独立开发

接下来完成 [独立项目：活动报名准备](08-independent-project.md)。它给出独立输入输出、fixture 样本、协议选择、建议脚手架、明确提交物和 P1–P8 人工验收。你需要新建活动、人数和参与方式的契约，不能直接复制旅行字段名。

推荐先用项目支持的 A2UI v0.9.1 生成表单，再以确定性处理器完成只读查询。页面解释样本余量和准备要求，不占座、不生成报名记录，也不访问真实 API 或 LLM。作业中的路径和故障开关需要自己实现。

按以下顺序留下迁移证据：

1. **写契约**：提供一次成功、一次业务不可用和一次非法输入的 JSON，指出业务校验由谁负责。
2. **解释边界**：沿编辑、action、适配器、查询结果、界面更新说明消息方向与权威状态。
3. **实现闭环**：展示所选协议的实际版本与传输模式，保留输入快照、原始消息和对应函数。
4. **验证失败**：制造查询失败、非法声明、响应乱序和等待时继续编辑，证明草稿与最后有效状态仍在。
5. **请人复现**：按 P1–P8 逐项记录预期、实际结果和证据；未执行项写明原因。

需要对照组合方式时，可阅读 [活动报名联合示例](labs/enrollment-workflow.md)，再回到自己的实现。协议组合需要联合契约；能打开几个面板不能证明它们已经共享同一条业务链路。

预测反馈验证局部理解，独立实现与人工验收验证此范围的迁移能力。如果由维护者组织首次学习观察，使用 [首次学习验收：任务与观察记录](09-learning-validation.md) 的任务卡和空白模板；当前尚未实际招募或观察读者，不把方案写成学习结果。
