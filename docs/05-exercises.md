# 练习清单

每个练习先写下预测，再动手修改，最后对照检查器验证。建议先完成聊天内的 [交互学习实验](07-learning-method.md)，再做下面的源码练习。

## 先在聊天里完成三个小任务

| 任务                       | 操作                                                               | 完成证据                                                                                    |
| -------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 改一条文本增量             | 回放选中 `TEXT_MESSAGE_CONTENT`，只修改 `delta` 并试运行           | 独立预览改变，真实回复不变；能指出更新前后文字                                              |
| 让预算进入动作             | 给普通表单增加预算字段、模型值、布局引用和 action 绑定，应用后提交 | action 的预算为 `4200`，处理结果回显相同值；本地走 `/api/a2ui/action`，Pages 为浏览器内处理 |
| 分别改变工具数据和 UI 资源 | 执行 MCP 实验 A，再执行实验 B                                      | A 的增量为 0 次资源读取、0 次挂载、1 次工具调用；B 为 1、1、0                               |

先自己完成预测，再看面板解释。每项留下一条检查器记录，并用一句话说明“什么输入经过哪个函数，使哪部分界面改变”。本地实验记录和网络协议消息要分开说明。

## AG-UI

1. 把一次文本回复改成不同大小的片段。前端文字相同，trace 是否相同？
2. 先发状态快照，再只更新其中一个字段。解释为什么界面无需重新获取全部数据。
3. 在工具参数尚未传完时取消。检查后续是否还有状态或消息更新。
4. 触发错误，确认 UI 不把错误当作成功。再次运行，旧请求是否会污染新请求？
5. 给工具结果新增一个字段，确保由结果或状态驱动的卡片显示它。

阅读线索：`shared/agui-agent.ts`、`shared/agui.ts`、`src/components/AguiChatTurn.tsx`、`src/components/AguiLearningPanel.tsx`；独立实验见 `src/labs/AguiLab.tsx`。

## A2UI

1. 修改标题文字而不修改组件 ID。解释组件身份和显示内容的区别。
2. 修改表单值，找到数据模型中对应的路径。再查看提交动作中解析后的值。
3. 新增一个受支持的组件；再使用一个不支持的组件，观察明确的失败反馈。
4. 尝试不存在的绑定路径，理解“空值”和“格式非法”应该如何区分。
5. 删除 surface，再重新生成。解释 UI 状态何时被清空。

阅读线索：`shared/a2ui.ts`、`shared/a2ui-agent.ts`、`src/labs/A2uiLab.tsx`、`src/components/A2uiWorkshop.tsx`。删除 Surface 的按钮位于独立实验 `/#a2ui`；聊天 Workshop 使用“重置为初始声明与模型”。

## MCP Apps

1. 查看工具列表中的 UI 资源关联，再观察资源读取结果。
2. 区分 MCP 的 `initialize` 与 iframe 中 App 的 UI 握手。它们分别连接谁？
3. 在应用中改变选择，追踪 App → Host → MCP Server → Host → App。
4. 切换到另一个独立实验，确认旧桥接连接已清理；再打开 MCP 实验，检查新的握手。仅打开文档会保留 App，不能当作卸载。
5. 修改本地工具返回值，重开应用并观察 `structuredContent` 如何进入 App。

阅读线索：`shared/mcp-server.ts`、`src/mcp-app.ts`、`src/labs/McpLab.tsx`。

## 验证三个进阶闭环

1. [A2UI 兼容与编辑冲突](labs/a2ui-compatibility.md)：保存一个动作后继续编辑，制造远端更新并解决冲突。提交旧动作，确认成功计数没有增加；丢失回执后先读取远端，检查后续草稿仍在。
2. [任务恢复与事件重放](labs/task-recovery.md)：开始后断开接流，记录 task/run 与游标，再恢复。证明接续同一个 run、投影与 checkpoint 一致、已提交的本地工具结果计数不重复。本地刷新恢复与 Pages 刷新清空分别验证。
3. [人工确认与业务事实](labs/human-approval.md)：修改提议使旧授权失效；模拟确认事务成功但响应丢失，查询事实，再用原命令重试。以同一报名 ID 和记录数 1 证明幂等。

每项保留输入、关键记录和结果，用一句话说明权威状态在哪里、结果未知时先查询什么。它们是独立实验；[活动报名联合示例](labs/enrollment-workflow.md) 展示了如何另行定义联合契约，将表单、确认与事件恢复连成同一任务。

## 独立迁移：只读活动报名准备

完成前面的局部改动后，按 [独立迁移任务](08-independent-project.md) 实现一个新场景。用户选择活动、人数和参加方式，查询样本余量与准备要求；结果必须说明“尚未报名”，不连接真实 API 或 LLM，不占座或产生报名记录。

任务给出成功与失败的输入输出、受支持协议选择和 `enrollment-prep` 建议脚手架。最低交付如下：

| 交付     | 要留下的证据                                                              |
| -------- | ------------------------------------------------------------------------- |
| 独立契约 | `eventId`、`attendeeCount`、`attendanceMode` 的规则、fixture 与运行时校验 |
| 协议闭环 | 点击前的本地绑定、解析后的动作、规范化查询、结果与界面更新                |
| 状态归属 | 当前草稿、提交输入、最新查询与最后有效结果分别由谁保存                    |
| 失败保留 | 非法输入、查询失败、非法声明、响应乱序和等待时继续编辑的前后对照          |
| 人工验收 | P1–P8 的预期、实际结果、原始记录与通过状态；所选协议附加案例              |

先写下预测，再实现，再请另一位开发者按步骤复现。没有实现时记“设计完成”，没有失败证据时记“待验收”，不能只凭成功截图记为完成。首次读者观察另用 [首次学习验收：任务与观察记录](09-learning-validation.md)；目前只有方案，尚未实际招募或观察。

## 组合挑战

需要联合参考时，查看 [活动报名联合示例](labs/enrollment-workflow.md) 与 [对应实验](#labs/enrollment-workflow)。独立迁移作品仍需自己定义契约、实现并验收。完成只读任务后，可按具体产品目标继续扩展：

- 设计 AG-UI 与 A2UI 的联合契约，写清载荷版本、路由和失败处理。若选择自定义事件，需要先扩展接收端；当前基础 AG-UI reducer 会拒绝未实现事件。
- 在自己的 Host 中同时支持普通工具文本结果和 MCP App UI 资源，根据工具元数据选择展示方式，并验证不支持 Apps 时的文本降级。
- 将 fixture 查询替换为真实业务查询 API，保持输入与结果校验；若另行增加写入，先定义授权、确认、幂等和业务事实查询。

这些扩展需要自己的实现与验证，不属于只读迁移任务的最低交付。真实 API、模型接入与报名写入不能因为存在联合参考就视为已完成。
